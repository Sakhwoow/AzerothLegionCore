# 2026_10_12_01_world.sql.gz / 2026_10_12_01_hotfixes.sql.gz

Источник: база данных стороннего репака **SPPNXT V9.10.1 [7.3.5] Legion** (публичный
дистрибутив сервера, развёрнут локально для анализа, не связан с AzerothLegionCore).

Формат: `mysqldump --no-create-info --insert-ignore` — чистые данные, без изменения структуры
таблиц, `INSERT IGNORE` не перезаписывает уже существующие строки (сначала собирался и
проверялся локально на копии боевой базы, см. ниже).

Применение:
```bash
gunzip -c 2026_10_12_01_world.sql.gz | mysql legion_world
gunzip -c 2026_10_12_01_hotfixes.sql.gz | mysql legion_hotfixes
```
Требуется рестарт worldserver — часть таблиц (hotfix-зеркала, в т.ч. переводы) кешируется в
памяти при старте.

## Методика

1. Полный систематический проход по всем таблицам обеих баз репака (`legion_hotfixes`: 812
   таблиц, `legion_world`: 312 таблиц) — таблица за таблицей, сравнение количества строк и
   схемы со своей базой.
2. Для каждой таблицы — проверка возможности переноса:
   - точное совпадение схемы → прямой перенос через `INSERT IGNORE`;
   - частичное совпадение (переименованные/лишние колонки) → явный маппинг по именам с
     разумными дефолтами для полей, которых нет у источника;
   - таблицы, завязанные на GUID конкретного спавна (`pool_creature`, `pool_gameobject`,
     `game_event_npc_vendor`) — **пропущены**: GUID между форками не совпадают, перенос создал
     бы ссылки в никуда;
   - таблицы со структурно другой моделью данных (`garr_mission`, `archaeology_digsites`,
     `spell_pet_auras`, `areatrigger_template`) — **пропущены**, перенос рискован без полной
     уверенности в семантике полей;
   - таблицы, где у нас уже есть критичные поля, которых нет у источника (например,
     `creature_classlevelstats.damage_exp1-5`, `reputation_reward_rate.quest_daily_rate` и т.д.)
     — **пропущены**, дефолт в 0 мог бы сломать баланс урона/репутации.
3. Заселение (`creature`/`gameobject`) переносилось по принципу "сколько экземпляров этого id
   у источника на этой карте vs у нас — добавляем только нехватку", не по приблизительным
   координатам (первая версия подхода давала задвоения, переделано).
4. После применения на боевой сервер обнаружены и вычищены точные дубли по позиции в
   `creature`/`gameobject` (2443 + 2298 групп) — все они унаследованы из исходного состояния
   боевой базы (существовали ещё до этого переноса, не вызваны самим переносом).

## Что сознательно не перенесено

- `legion_auth`/`legion_characters` базы репака — чужие тестовые аккаунты/персонажи/магазин,
  не контент.
- Содержимое, которого нет **и у самого репака** (~7-16k непереведённых NPC/квестов/объектов,
  ~36 "мёртвых" ID боссов из журнала рейдов, которых Blizzard давно заменила новыми) —
  закрыть можно только ручным переводом/разработкой.
